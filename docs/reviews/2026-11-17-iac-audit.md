# IaC としての監査（2026-11-17、main f6a524e）

Mamela を、IaC ツールとして厳しく調べた記録。5 つの観点（適用と状態、セキュリティ、gitops と運用、
核と拡張の分離、宣言・Pome・k3s 運用）を別々に読み取り専用で調べ、重大なものは再現プログラムで確かめた。
次のリリース（Mamela Pome 0.3.2）で直すものと、あとに回すものをここで決める。

凡例: **再現** = 実際に動かして起きることを確かめた。**読** = コードを読んだだけ（直すときに、先に落ちるテストを書いて確かめる）。
規模: 小 = 1 ファイル前後、中 = 数ファイルと文書、大 = 設計から。

## 核と拡張（k3s の分離）

- k3s の文字列を含む非テスト行は 455 行・21 ファイル。移動量は、宣言名に k3s と出ない混在関数を入れて **1,100〜1,300 行**（設計文書の「約 450 行」は過小）。`plan.go` の k3s は約 330 行（全体の 35%）。
  - 実装後（段 0〜4、0.3.2）: `internal/ext/k3s` へ移した非テストのコードは約 1,700 行（コメント込み。graph 360、plan 460、policy 30、node provider 300、mamelet 570）、核に足した登録の口は約 700 行。ゴールデン（plan 37 場面、graph、revision、mamelet の報告、manifest と ProvidersDigest、Decide 表、許可プログラム）は段 1〜4 で不変。核に残る k3s は wire・保存の形（`noderev`、`state`、`names`、`store` の参加トークン）と `mamelet.System` の設定欄で、段 5（0.4）で動かす（[設計](../design/node-extensions.md)）。
- 設計文書（案 A）は成り立つ。ただし次を直す。
  1. 段 0 に、**ゴールデンテスト**を置く。既存のテストには固定 digest がなく、plan JSON に入る文言を 1 字変えると承認が無効になる。置き場所は `internal/plan/testdata/golden/`。
  2. plan の継ぎ目に、マシン再起動の関門・サービス起動の関門・`nodeReported`・`Deleted()` の口も要る。
  3. 拡張が `Auto` を返して承認を迂回しないよう、核が登録した op を `ApprovalRequired`/`Denied` に制限する。
  4. 理由コードは据え置き（plan JSON に入る）。登録時に重複を検出する。拡張の名前と版を provider の manifest（`ProvidersDigest`）に入れる（全 plan の digest が変わるので、段 5 で行う）。
  5. mamelet の許可プログラム一覧は、拡張の和集合になるので、出荷する mamelet ごとに固定するテストを置く。
  6. 未知の拡張の revision は、revision 全体ではなく未知のキーだけを `Refused` にする（全体を断ると mamelet の更新も止まる）。
- 段 5（wire の `Ext`）は digest が変わる唯一の破壊的な段で、旧 mamelet が未知のメンバーを丸ごと断る。CP の二重 decode と `accepts`、mamelet の更新が前提になる。**0.4 に回す。**
- 線引き: 核は署名つき revision・grant の失効・plan と policy のエンジン・store・保護ノード・mamelet の本体と更新。`ext/os`（常に組み込む）は package（apt）・service（systemd）・mamelet の kind。拡張は k3s・manifest・ノード削除・k3s の token と観測。
- 核に残る Proxmox/AWS の知識: `auth="proxmox"` と AWS SigV4・`~/.aws/credentials` の読み取り（mamela の依存に AWS/smithy 28 パッケージ。mamelet と mamelacd は 0）、wire・DB・設定の `vmid`、`qemu-guest-agent` の固定導入。0.4 で出す。

- パッケージ依存の逆向き: `site`→`provider/node`→`store`、`cp`→`mamelet`、`state`→`noderev`、`plan`→`noderev`。
- 巨大関数（行数）: `runAct` 220、`runImport` 203、`runControlPlane` 195、`Reconciler.Apply` 184、`graph.Validate` 171、`Agent.act` 161。
- examples: `kv` は 14 ファイルが使う契約のフィクスチャなので残す。`ec2` は AWS の知識（catalog 17.7 KB と fake）で、homelab と 3 テストが依存する。kv で置き換えて縮める。`provider.wasm` は 11.3 MB で、履歴の 46 コミットが変えた（pack の 94%）。git から外してテスト前にビルドする。

## 良い点

- 承認は digest の完全一致（`LoadPlan` が毎回再計算して照合）。provider・endpoint・保存済み program の digest 固定。
- ノードの mTLS（CN と DB の serial の突き合わせ）、revision の Ed25519 署名（node・VMID・serial・期限）。mamelet の許可プログラムと引数の正規表現、tar の展開の拒否、更新は sha256 一致後だけ `-version` を実行。
- WASM の import の allowlist、toolchain の sha256 固定、CI の action の commit 固定。`go vet` は指摘 0 件、`-race -shuffle` でも不安定なテストは見つからなかった。
