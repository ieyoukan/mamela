# 宣言に追従する削除と、構成ごとの管理範囲

- 状態: [ADR 0013](../adr/0013-removal-deletes.md) が小さくして実装した。この文書は、ADR に入れなかった案を残す。
- 日付: 2026-11-12（2026-11-14 に ADR 0013 で実装）

## ADR 0013 に入ったもの

- 宣言の名前（stack）による管理範囲。作成の記録に持たせた。
- 宣言から消えた物の削除。provider の `removes` の操作で、plan に載せ、ホストでの承認で進む。
- 削除後の、作成の記録とマシンの登録の失効。応答喪失・古い plan・名前の再利用への備え。
- 後から足した例外: Mamela が引き継いだ物（`mamela act` の引き継ぎ。作成の記録の `plan_digest` が `act:` で始まる）は削除しない（MAM-PLAN-0308）。観測だけ（observe-only）の名前の物も削除しない（MAM-POL-0312）。どちらも plan は残す理由を示す。

## 入れなかったもの（要るときに足す）

- **ライフサイクルの設定:** 当初の案の `on_remove = retain|delete` と `deletion_approval = required|automatic`。今は、policy の `removal = "retain"` で全体を止められるだけである。無人の削除（`automatic`）は、GitHub の側から消せない、という ADR 0013 の前提を崩すので、入れない。
- **リソースごとの retain:** 手放すには、Pome の名前を変える。
- **rename の追跡:** 名前を変えると、削除と新規作成になる（削除は承認が要る）。
- **共有依存:** テンプレートのように、ほかの物が頼る物は、その種類が `removes` を持たなければ消えない。
- **ノードの上の物:** package・service・k3s を宣言から消したときに、ノードの上の物を戻す処理。
- **前回適用した宣言の保存:** provider の依存を宣言から外すと、その provider は動かず、その物は残る。
