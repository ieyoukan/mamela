# ADR 0013 — 宣言から消えた資源は、その宣言が作ったものに限って、承認つきで削除する

- 状態: Accepted（2026-11-14）
- 日付: 2026-11-14
- 対象: ADR 0002・0006（削除は計画に入れない、を改める）、0012（承認の場所）。[宣言に追従する削除](../design/declarative-removal.md)の案を、小さくして実装したもの

## 文脈

これまで、宣言からリソースを消しても、実物は残った。削除は、provider の明示操作を人が `mamela act --confirm` で送るときだけだった。安全だが、宣言を実物に揃える道具としては欠けている。宣言に無い VM が増え続け、後片付けに別の手順が要る。

一方、削除は取り返しがつかない。次の二つを破ってはならない。

- **別の宣言の物を消さない。** 同じ Control Plane が、複数の宣言（構成）の物を持つ。観測した Mamela の物のすべてを「宣言に無いもの」として消すと、別の構成の VM を消す。
- **GitHub の側からは壊せない。** mamelacd は GitHub の入力を扱う。そこから届く承認で削除が走れば、PR の書き手と承認コメントを偽れる者が、実物を消せる（[ADR 0012 の信頼の範囲](0012-mamelacd.md)）。

## 決定

### 1. 消すのは、次をすべて満たす物だけ

1. provider が観測し、Mamela が作ったと記録している（Foreign は対象外）。
2. 作成の記録の宣言（stack）が、いま plan する宣言と同じ。
3. いまの宣言に、そのリソースが無い。
4. その種類が、provider の契約で削除する操作（`removes`）を持つ。
5. policy の `removal` が `retain` でない（既定は `delete`）。
6. Control Plane 自身のホストでない（MAM-POL-0308）。

どれかを満たさない物は、これまでどおり残す。plan は残す理由を示す。

| コード | 残す理由 |
|---|---|
| MAM-PLAN-0302 | 別の宣言が作った |
| MAM-PLAN-0303 | どの宣言が作ったかを記録する前に作った |
| MAM-PLAN-0304 | provider にその種類を削除する操作が無い |
| MAM-PLAN-0305 | policy が残す（`removal = "retain"`） |
| MAM-PLAN-0306 | provider が削除を用意できなかった |
| MAM-POL-0308 | Control Plane 自身のホスト |

### 2. 宣言の名前（stack）

stack は、宣言の Pome の名前（`Pome.toml` の `[pome] name`）である。書き手が決め、どこに checkout しても変わらない。ディレクトリの名前やパスからは作らない。

- 作成の記録（`provider_creations`）に stack を持たせる（migration 17）。以前の記録は stack を持たず、削除の対象にならない。人が `mamela claim <dir> --confirm` で、その宣言が宣言している物のうち stack の無いものに、宣言の名前を記録できる（`--confirm` なしでは一覧だけ）。別の宣言の物は変えない。
- 同じ Control Plane の宣言には、互いに違う Pome の名前を付ける。同じ名前なら、同じ宣言として扱う。
- Pome の名前を変えると、それまでの物は残る（消えない）。
- 名前の無い Pome の物は、stack を持たず、削除の対象にならない。

### 3. plan

削除は plan に載る。`- ProxmoxVM web [needs approval]` と表示し、送る要求まで示す。

- 判定は、いつも「要承認」（MAM-POL-0310）。カタログが知らない要求を含めば拒否（MAM-POL-0311）。
- 削除は、ほかのすべての変更のあとに、新しい物から順に行う（後から作った物は、前の物に頼る）。
- plan は、いつもと同じく、何も実行しない。

### 4. 承認は Control Plane のホストで行う

削除を含む plan は、`mamela approve` を Control Plane のホストで実行した承認だけで進む。`mamela api`（mamelacd 向け）は、削除を含む plan の承認を断る（MAM-API-0201）。PR のコメントでは承認できない。

これで、GitHub の側が乗っ取られても、物は消えない。承認のあとの apply は、これまでどおり mamelacd がブランチの先頭の宣言だけに対して行える。

### 5. apply

明示操作（`mamela act`）と同じ手順で行う。

1. guard（前）。
2. 意図を記録する（`explicit_operations`）。
3. 削除の変更だけの許可で送る。
4. 物が消えたと、provider の一覧で観測してから、作成の記録とマシンの登録を終える（同じ名前で作り直した物が、古い証明書や許可を引き継がない）。
5. guard（後）。

- 応答が失われたら、送り直さない。物がもう無ければ、記録だけを終える。
- 承認のあとに物が変わっていれば（バージョンが違えば）、何も消さず止まる（MAM-REC-0002）。
- 削除の前の変更が失敗すれば、何も消さずに止まる。

### 6. 範囲に入れないもの

- **ノードの上の package・service・k3s:** 宣言から消えても、ノードの上の物は変えない（VM ごと消えるときは消える）。
- **リソースごとの retain、rename の追跡:** 要るなら、Pome の名前を変えて手放す。
- **無人の削除:** 承認の自動化は無い。

## 検討したが採らなかったもの

- **観測した Mamela の物をすべて消す:** 別の宣言の物を消す。
- **PR のコメントで削除を承認する:** GitHub の側が破られると、削除が走る。
- **ディレクトリやリポジトリから stack を作る:** checkout の場所で変わる。
- **削除の判定を provider に任せる:** 契約が決めるのは「削除する操作がある」ことまで。何を消すかを決めるのは Mamela である。

## 結果

- 宣言を実物に揃える道具になる。消す範囲は、宣言が作った物に限る。
- 削除の承認だけは、GitHub の外にある。PR は削除を提案でき、Control Plane の人が承認する。
- provider は、削除する種類に `removes` を付ける。付けない種類は消えない。
- 以前の物（stack を記録する前に作った物）は、`mamela claim` でその宣言の物にするか、`mamela act` で消す。
