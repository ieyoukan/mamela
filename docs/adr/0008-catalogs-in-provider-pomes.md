# ADR 0008 — API のカタログは、プロバイダーの作者が書き、Pome に同梱する

- 状態: Accepted（2026-11-11）
- 日付: 2026-11-11
- 対象: カタログ（ADR 0002、0005、0007）の持ち主と配り方。ADR 0006（本体は特定の基盤を知らない）の仕上げ

## 文脈

カタログは、API の各呼び出しについて、次のことを書いたものである。

- 効果（読む、作る、変える、再起動する、データを失う）
- パラメータの場所
- 対象を名指すパラメータ（`bind`）
- 許す値（`values`）
- 大きさの測り方（`measures`）

host は、プロバイダーのプログラムが送るすべての要求を、カタログで分類する。プログラムが自分の呼び出しを自己申告で分類すれば、削除を「読み取り」と言って、データを失う操作の禁止をすり抜けられる。そのため、カタログはプログラムとは別に、host の側になければならない（ADR 0002）。

ADR 0005 と 0007 までは、Mamela 本体がカタログを持っていた。`provider/catalogs` の EC2・ECS・CloudWatch Logs・SSM・IAM・Proxmox で、`catalog = "builtin:<名前>"` で使った。これには次の問題がある。

- **本体が基盤を知る:** Mamela 本体が、AWS と Proxmox の知識を持つ。ADR 0006 の「本体は特定の基盤を知らない」とぶつかる。
- **API を知らない者が書く:** 新しい API のたびに、Mamela 本体の変更と版上げが要る。カタログを書くのに最もふさわしいのは、その API を使うプロバイダーの作者である。
- **Go に縛られる:** カタログは Go のコードで、Go を読まない利用者には読みにくい。プロバイダーは定数を import するので、Mamela の版に縛られ、Go 以外の言語でも書きにくい。

## 決定

### 1. カタログはデータで、プロバイダーの作者が書く

- **形式:** カタログは `mamela-catalog/v1` の JSON とする（`protocol.DecodeCatalog`）。
  - `schema` は必須。
  - 未知のメンバーは拒む。
  - 呼び出しの形は `Check` で確かめる（今までと同じ）。
- **書き方:** 作者は、手で書いても、コードから書き出してもよい。
  - mamela-aws と mamela-proxmox は、Go の `catalogs` パッケージを `build.sh` で `pome/catalogs/*.json` に書き出す。
  - 同梱する JSON が書き出しと同じことを、試験で確かめる。
- **Mamela 本体:** カタログの形式と、それを使った強制（分類、`bind`、`values`、`measures`、データを失う変更の禁止）だけを持つ。特定の基盤のカタログは持たない。

### 2. Pome に同梱し、運用者が名指したときだけ使う

- **同梱:** プロバイダーの Pome に、プログラムとは別のファイルとして入れる。`mamela-provider.toml` の `[catalogs]` に、名前と Pome の中のファイルを並べる。
  - Pome の版は git のツリーで、`Pome.lock` と sumdb で固定される。カタログも、プログラムと同じ鎖で固定される。
  - Mamela は Pome を読むときに、各カタログが Pome の中のファイルで、形式として正しいことを確かめる。
- **選ぶ:** 運用者は、`mamela.providers.toml` の API の節で、`catalog = "pome:<名前>"` と名指す。自分のファイルを名指してもよい。
  - 名指さなければ、カタログはない。その API の呼び出しはすべて分類できず、変更のたびに人の承認が要る。
  - 同梱されていても、名指さないカタログは使わない。Pome を足しただけで、運用者の知らないカタログが効くことはない。
- **読む:** `mamela provider catalog [--json] <pome-dir> [<provider>]` で、同梱するカタログの効果・`bind`・`values`・`measures` と sha256 を読める。`mamela provider inspect <provider-pome-dir>` は、プログラムの呼び出しを、Pome のカタログで分類して見せる。
- **`builtin:`:** 拒む。メッセージで、この ADR と `pome:` を示す。

### 3. カタログは plan と一緒に保存し、承認の範囲に入る

- **保存:** Mamela は、プロバイダーのプログラムと一緒に、同梱するカタログを plan に保存する（SQLite の `plan_catalogs`、内容で番地づけ）。apply は、保存したカタログで分類する。キャッシュや Pome が後で変わっても、plan と同じバイト列である。
- **承認の範囲:** カタログの中身は、今までどおり接続先の識別に入る。カタログが変われば承認は効かない（MAM-REC-0007）。

### 4. プログラムは、カタログを見ず、変えられない

ADR 0002 の境界は変わらない。

- プログラムは隔離されて動き、カタログを受け取らない。
- host は、運用者が選んだカタログで、プログラムのすべての要求を分類する。

信頼の形は、変わる。

- **これまで:** 「Mamela がレビューしたカタログ」
- **これから:** 「運用者が読み、名指した、固定された版のカタログ」

作者が同じでも、カタログはプログラムと別のファイルで、人が読める。運用者は、カタログを読まずにプロバイダーを使うこともできる。そのときは、変更のたびに人の承認が要る。

## 結果

- **本体:** 特定の基盤のコードもデータも持たない。
- **作者:** 新しい API のプロバイダーを、Mamela 本体を変えずに書ける。カタログの変更は、プロバイダーの版で配る。
- **Go に縛られない:** Go 以外で書くプロバイダーも、JSON のカタログを同梱できる。プロバイダーは Mamela の Go のカタログを import しない。
- **運用者:** 使う前にカタログを読める。カタログを広げる（IAM に許すポリシーを足すなど）には、作者が直し、運用者が読んで選び直す。
- **移したもの:**
  - EC2・ECS・Logs・SSM・IAM のカタログ: `github.com/ieyoukan/mamela-aws`
  - Proxmox のカタログ: `github.com/ieyoukan/mamela-proxmox`
  - 例の EC2 のプロバイダー: `examples/ec2/pome/catalogs/ec2.json`
- **移行:** 運用者の `mamela.providers.toml` の `builtin:<名前>` は、`pome:<名前>` に書き換える。
